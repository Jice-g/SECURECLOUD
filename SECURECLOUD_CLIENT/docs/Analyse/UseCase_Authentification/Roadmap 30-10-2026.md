## 1. Décision de cadrage du 30/10/2026

On suspend :

1. **La complétion générale du domaine** (modèle, repositories, services restants).
2. **L'optimisation générale** (nettoyage d'arborescence, refactorings, performances).
3. **Tout le périmètre Alertes** (UC-10, UC-11, UC-12).

On avance en **tracer bullet** : une seule tranche verticale, du clic UI jusqu'à `auth-service` et retour,
avec des tests. Elle remplace le « Sprint 5 : passerelle Application » du plan précédent, avancé volontairement
pour valider le design avec un vrai scénario.

Principe : **on ne code dans le domaine que ce que Login exige.** Le reste attend ici.

## 4. Reporté : dette et optimisation

| Élément | Détail |
|---|---|
| **`IMessageRepository.h` à réparer** | Ne compile pas en l'état (classe vide + redéfinition, `Result<>` non défini, `DeliveryStatus` inexistant). Détail et correctif dans `LoginFeature.md` §2. À traiter dès que le dépôt a un CMake commun, **avant** de lier ce header à une cible. |
| Points relevés dans `domain.zip` | Voir `DomainReview.md` : `UserLogin` (espaces internes), `DirectConversation` accepte deux fois le même participant, un test sans aucun `CHECK`, 2 tests enregistrés deux fois, warnings `-Wreorder` / `-Wparentheses` / `-Wswitch` |
| Nettoyage de l'arborescence | Doublons `User.h` / `MessageContent.h`, faute « Attachement », collision `ui/Attachment.*` → `AttachmentWidget`, éclatement de `SQLiteRepository.h` en un fichier par interface |
| `StrongId<Tag>` générique dans `shared/` | À faire quand on ajoute le 2e `Id` ; Login n'en a besoin que d'un (`UserId`, existant) |
| Suppression de `LogSessionService` | Proposition : le cycle de vie va dans `Session` |
| Coffres natifs OS pour clés et tokens (DPAPI, Secret Service, Keychain) | CLIENT-03, **RM** |
| MFA (TOTP) | Champ réservé dans le contrat Login ; implémentation hors tranche |
| Récupération d'identifiant / de mot de passe | UC-01 alternatives, hors périmètre SK, à documenter comme limite |
| Persistance du refresh token entre deux lancements | Login v0 garde les tokens **en mémoire seulement** |
| Refresh automatique des tokens (`POST /auth/refresh`) | Après Login ; dépend de la durée de vie du token |
| Mesures de démarrage < 2 s et RAM < 50 Mo | QT-02, quand l'UI sera plus complète |
| Build macOS | Best effort (QT-01) |
